Example Use Cases

NGINX as a Reverse Proxy

NGINX is commonly used as a reverse proxy to route traffic to backend services.

Why Use NGINX as a Reverse Proxy?

  • Load balancing
  • SSL termination
  • Caching and compression
  • Security enhancements

Docker Implementation

docker network create my_network

docker run -d --name backend --network my_network my_backend_image

docker run -d --name nginx --network my_network -p 80:80 nginx
graph LR; A[Client] -->|Request| B[NGINX Proxy]; B -->|Forward| C[Backend Service];

Private Connection: Frontend & Backend

Ensuring a secure communication channel between frontend and backend.

Why Use Private Networking?

  • Prevents direct access from external sources
  • Improves security and data integrity
  • Reduces potential attack vectors

Docker Implementation

docker network create app_network

docker run -d --name backend --network app_network my_backend_image

docker run -d --name frontend --network app_network -p 3000:3000 my_frontend_image
graph LR; A[Frontend] -->|Private Network| B[Backend];

Backend & Database Network

Linking backend services securely to a database.

Why Secure Backend-Database Communication?

  • Ensures that only backend services can communicate with the database
  • Protects sensitive data from unauthorized access
  • Reduces the risk of SQL injection attacks

Docker Implementation

docker network create db_network

docker run -d --name database --network db_network -e POSTGRES_PASSWORD=mysecretpassword postgres

docker run -d --name backend --network db_network -e DB_HOST=database my_backend_image
graph LR; A[Backend] -->|Queries| B[Database];
